## 1. INTRODUCTION

### What is Next.js
Next.js is a React framework for building web applications, providing additional features beyond React's view layer.

### Why learn it

Next.js simplifies web application development for production with features like file-based routing, API routes, and optimized rendering.

- 1. Routing : files bases routing
- 2. API routes : permit to create api routes
- 3. Rendering: SEO
- 4. Data fetching
- 5. Styling
- 6. Optimization
- 7. Dev and prod build system

### Pre-required

To get started, a solid understanding of HTML, CSS, JavaScript (ES6+), and React fundamentals is required.

### Project folder structure

When structuring a Next.js project, it's important to organize the files and directories in a way that makes the project easy to navigate and maintain. Here is a common and recommended folder structure for a Next.js project:

```
my-nextjs-app/
├── .next/                  # Automatically generated, do not modify
├── node_modules/           # Automatically generated, do not modify
├── public/                 # Static files such as images, fonts, etc.
│   ├── favicon.ico
│   ├── images/
│   └── ...
├── src/
│   ├── components/         # Reusable components
│   │   ├── Header.js
│   │   ├── Footer.js
│   │   └── ...
│   ├── pages/              # Page components
│   │   ├── api/            # API routes
│   │   │   ├── hello.js
│   │   │   └── ...
│   │   ├── _app.js         # Custom App component
│   │   ├── _document.js    # Custom Document component
│   │   ├── index.js        # Home page
│   │   └── ...
│   ├── styles/             # Global styles and CSS modules
│   │   ├── globals.css
│   │   ├── Home.module.css
│   │   └── ...
│   ├── utils/              # Utility functions and helpers
│   │   ├── api.js
│   │   └── ...
│   └── ...
├── .env.local              # Environment variables (local)
├── .gitignore              # Git ignore file
├── jsconfig.json           # JS configuration
├── next.config.js          # Next.js configuration
├── package.json            # Project metadata and dependencies
├── README.md               # Project documentation
└── yarn.lock / package-lock.json  # Lock file for dependencies
```

### Explanation

- **`.next/`**: Automatically generated by Next.js during build and development. Contains build output.
- **`node_modules/`**: Contains installed npm/yarn packages.
- **`public/`**: Contains static assets like images, which are served directly.
- **`src/`**: Main source directory for the project.
  - **`components/`**: Contains reusable React components.
  - **`pages/`**: Contains page components that map to routes. Files inside `pages` directory are automatically routed based on their filename.
    - **`api/`**: Contains API route files. Each file in this directory corresponds to an API endpoint.
    - **`_app.js`**: Custom App component to customize the default App behavior.
    - **`_document.js`**: Custom Document component to augment the default HTML document structure.
    - **`index.js`**: The home page of the application.
  - **`styles/`**: Contains global CSS and CSS modules.
  - **`utils/`**: Contains utility functions and helpers.
- **`.env.local`**: Contains environment variables for local development.
- **`.gitignore`**: Specifies files and directories to be ignored by Git.
- **`jsconfig.json`**: JavaScript configuration file for module resolution.
- **`next.config.js`**: Custom Next.js configuration.
- **`package.json`**: Contains project metadata, scripts, and dependencies.
- **`README.md`**: Documentation for the project.
- **`yarn.lock` / `package-lock.json`**: Lock file for dependencies to ensure consistency across installations.

### React Server Component

#### 1. Server Component
- In Next.js, all components are Server Components by default.
- The have the ability to run tasks like reading files, fetching data, and manipulating data before rendering the component.
- However, they don't have access to the DOM, and they can't interact with the browser.
  
#### 2. Client Component
- Client components are React components that run in the browser.
- To create a client component, it's necessary to add the `use client` directive at the top of the component.
- Client components can't perform tasks like reading files, fetching data, or manipulating data before rendering but they can interact with the browser by using the DOM and hooks.
  
#### 3. React Server Components and Routing
- React Server Components are used to render pages on the server by awaiting certain tasks before rendering the page.
- Client components are use to leverage hooks from the routing module


## 2. Routing
- In Next.js, routing is based on a file system, where URL paths are defined by files and folders within your code base.
- Routes must be placed inside the `app` folder, which is within the `src` folder.
- Every file that represents a route should be named `page.js` or `page.tsx`, depending on whether TypeScript is used.
- Each folder in the `app` folder corresponds to a part segment in the browser URL.
- The `page.tsx` file within the `app` folder maps to the root of your domain.
- If a URL cannot map to a file in the `app` folder, Next.js will automatically respond with a 404 not found response.

### Nested routes
- Nested routes are defined by placing a folder inside the `app` folder.
- By creating a folder inside the `app` folder, you can create a nested route.
- For example, if you have a route called `blog` and you want to create a nested route called `post`, you would create a folder called `post` inside the `blog` folder.
- The `post` folder would then contain a `page.tsx` file, which would map to the `/blog/post` URL.

### Dynamic routes
- Dynamic routes are defined by using dynamic parameters in the URL.
- Dynamic parameters are defined by using the `[param]` syntax in the URL.
- For example, if you have a route called `blog` and you want to create a dynamic route for a specific post, you would create a folder called `[post]` inside the `blog` folder.
- The `[post]` folder would then contain a `page.tsx` file, which would map to the `/blog/[post]` URL.
- The `[post]` folder would also contain a `page.tsx` file, which would map to the `/blog/[post]/[comment]` URL.

### Catch all segment

The catch all segment is a special segment that matches any URL path that doesn't match any other route.

For example, if you have a route called `blog` and you want to create a catch all route for all posts, you would create a folder called `[...post]` inside the `blog` folder.

###  Not found

If a URL cannot map to a file in the `app` folder, Next.js will automatically respond with a 404 not found response.

### Private folder

The `app` folder is a private folder, which means that it's not accessible from the browser.

## Layouts

A layout in Next.js is UI shared between multiple pages, such as a header and footer.

Layouts can be created by default exporting a React component from a layout.js or layout.tsx file.

The layout component should accept a children prop, which is populated with a child page during rendering.

Next.js provides a root layout in the app folder, which is mandatory for every Next.js application.
The root layout can be customized by adding elements like a header and footer inside the body tag.

The layout components should render the children prop for the child page to render its unique UI.
